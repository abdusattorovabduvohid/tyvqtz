# Админ Панель

Full-stack админка на **Next.js 14 (App Router)** + **Mantine UI** + **Prisma/SQLite**.
Анимации — **Framer Motion**. Авторизация — JWT в httpOnly-cookie. Права — RBAC (секции × действия).

## Запуск

```bash
npm install
npm run db:push     # создать БД из схемы
npm run db:seed     # суперадмин + демо-роль
npm run dev         # http://localhost:3000
```

Тестовый вход: **admin / admin123**

## Скрипты

| Команда | Назначение |
|---|---|
| `npm run dev` | dev-сервер |
| `npm run build` / `npm start` | прод-сборка и запуск |
| `npm run db:push` | синхронизировать схему с БД |
| `npm run db:seed` | заполнить начальными данными |
| `npm run db:studio` | Prisma Studio (просмотр БД) |

## Что реализовано (ядро)

- **Логин** — анимированная страница, защита маршрутов через `middleware`.
- **Пользователи** — список (поиск, аватары) + создание/редактирование/удаление.
  Поля: логин, имя, фамилия, отчество, фото (загрузка), пароль, роль.
- **Роли** — список карточками + создание/редактирование с матрицей прав
  (секции × действия view/create/update/delete). Переключатель «Суперадмин» = все доступы.
- **RBAC** — меню и кнопки скрываются по правам; API защищён на сервере (`requirePermission`).

## Вагоны и этапы (реализовано)

- **Типы вагонов** — справочник (CRUD), название типа.
- **Этапы** — справочник этапов (номер, название, время на выполнение).
  Кнопка «Сгенерировать 23» создаёт стандартный набор этапов.
- **Вагоны** — создание (название, номер, тип). При создании вагон получает
  **снимок всех этапов** (23) по порядку.
- **Карточка вагона** — таймлайн этапов: назначение исполнителей, старт/завершение,
  **живой обратный отсчёт** (серверное время + polling каждые 5 сек), статусы
  (ожидает / в работе / просрочен / завершён). Этапы идут строго последовательно.
- **Мои этапы** — рабочий интерфейс исполнителя: назначенные ему этапы с таймерами
  и кнопками «Старт» / «Завершить».

## Уведомления (Web Push + Telegram)

Сотрудник включает уведомления сам на странице **«Уведомления»**
(`/dashboard/notifications`, пункт есть у всех, прав не требует).
События: создан вагон, ждём вашего согласования, ваша очередь принимать день,
день не принят, позиция закрыта, а также ежедневные напоминания по плану.

### Что настроить на сервере (Vercel → Settings → Environment Variables)

| Переменная | Зачем |
|---|---|
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | ключи Web Push (уже сгенерированы в `.env`) |
| `VAPID_SUBJECT` | почта или адрес сайта — от кого пуш |
| `APP_URL` | `https://<адрес сайта>` — из него строятся ссылки в уведомлениях |
| `TELEGRAM_BOT_TOKEN` | токен бота от [@BotFather](https://t.me/BotFather) |
| `TELEGRAM_BOT_USERNAME` | имя бота без `@` — для кнопки «Подключить телеграм» |
| `TELEGRAM_WEBHOOK_SECRET` | любая длинная случайная строка (защита вебхука) |
| `TELEGRAM_GROUP_CHAT_ID` | необязательно: общий чат/группа, куда дублируются важные события |
| `CRON_SECRET` | секрет для `/api/cron/notify` |

Новые VAPID-ключи при необходимости: `node -e "console.log(require('web-push').generateVAPIDKeys())"`.

**Про смену VAPID-ключей.** Подписка привязана к ключу на стороне push-сервиса
(Google/Apple), а не у нас в базе. Со сменой ключа старые подписки перестают
принимать отправки — приходит `403`/`401` вместо `410`, то есть «молча».
Поэтому в системе есть две страховки:

- сервер считает такие отказы (`PushSubscription.failCount`) и после 5 подряд
  выбрасывает подписку — временный сбой конфигурации подписки не убивает;
- `PushAutoHeal` (в `DashboardShell`) при входе сотрудника сверяет ключ его
  подписки с ключом сервера и, если они разошлись, тихо переоформляет её.
  Проверка идёт не чаще раза в 6 часов и только если разрешение уже дано.

То есть после смены ключей всё восстановится само в течение смены, но
**без нужды ключи всё равно не меняйте** и обязательно держите резервную копию
приватного ключа — потеря равносильна смене.

### Телеграм-бот

1. `@BotFather` → `/newbot` → получить токен, вписать в `.env` и в Vercel.
2. `node prisma/setup-telegram.mjs` — ставит вебхук на `APP_URL/api/telegram/webhook`
   и меню команд. Проверка: `node prisma/setup-telegram.mjs info`.
3. Сотрудник на сайте жмёт «Подключить телеграм» → открывается бот → `/start <код>`.
   Отключение — командой `/stop` или кнопкой на сайте.

Общий чат: добавить бота в группу, отправить туда `/id`, полученное число (с минусом)
вписать в `TELEGRAM_GROUP_CHAT_ID`.

### Напоминания по плану

`vercel.json` → cron `0 3 * * *` (03:00 UTC = 08:00 по Ташкенту) дёргает
`/api/cron/notify`. Он смотрит план дат вагонов и шлёт: «завтра начинается
позиция №N», «сегодня начинается», «позиция просрочена на K дн.»,
«ждём вашего согласования создания вагона».

Проверить руками: `curl "https://<сайт>/api/cron/notify?key=<CRON_SECRET>"`.

### Ограничения

- **iPhone**: пуши приходят только если сайт добавлен на экран «Домой»
  (Поделиться → «На экран «Домой»», iOS 16.4+). В обычной вкладке Safari — нет.
- Если сотрудник не дал разрешение браузеру — пуши не придут, останется телеграм.
- Мёртвые подписки (404/410 от push-сервиса) удаляются автоматически.
